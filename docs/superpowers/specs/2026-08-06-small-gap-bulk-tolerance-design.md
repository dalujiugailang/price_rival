# 小差额批量容忍设计

## 目标

在京东换新追价工作台的 `AZ提醒` 列头提供可配置的容忍边际底线和一键批量调整能力。系统对现有小差额提醒逐行模拟“按价格取整规则补至不低于天猫裸机价”，重新匹配补贴并计算追后边际利润率；满足容忍底线的 PPV 可以在二次确认后一次性应用。

同时将系统新产生的竞争力判断由严格 `>` 统一调整为 `>=`。历史正式落数保持原值，不回溯重算。

## 业务口径

### 小差额提醒范围

继续沿用现有提醒条件：

- 仅京东换新渠道。
- 存在有效 `tm裸机价`。
- 当前系统或手动推荐追后价相对 JD 当前价发生过调整。
- JD 当前价尚未达到天猫物品价竞争力。
- 当前推荐追后价尚未达到天猫物品价竞争力。
- 当前推荐追后价距 `tm裸机价` 的正向差额不超过 20 元。

报价量或成交量 Top 20% 的“高价值小差额提醒”标识继续保留。

由于竞争力口径改为 `>=`，当前价格或追后价格等于 `tm裸机价` 时已经具备竞争力，不再进入小差额提醒。

### 容忍试算价

价格取整逻辑优先。容忍试算价不是直接写入原始 `tm裸机价`，而是：

1. 以 `tm裸机价` 为最低目标。
2. 使用现有 `roundUploadPrice` 价格档位规则。
3. 向上寻找第一个 `>= tm裸机价` 的合法上传价格。

例如 `tm裸机价 = 1068` 时，`1060` 低于目标，不可采用；容忍试算价应为下一个合法价格 `1100`。

现有 `getRoundedCompetitivePrice` 调整为允许与竞品价格相等，并以 `targetPrice` 约束最低目标。常规 `tm裸机价 × 103%` 追价仍以 103% 为起点，因此该调整不会降低正常追价目标。

### 容忍资格

对每条小差额提醒：

1. 计算容忍试算价。
2. 按试算价重新匹配该新机系列的 AHS 补贴和京东补贴。
3. 按现有京东换新线性费用公式重算追后边际利润率：

```text
线性费用 = (试算价 + AHS 补贴) × 4.66% + 基准价 × 2.18% + 81
追后边际利润率 = 1 - (试算价 + AHS 补贴 + 线性费用) / 基准价
```

4. 试算追后边际利润率 `>= 容忍边际底线` 时，该 PPV 进入可容忍名单。

容忍边际底线默认 `-2.00%`，是独立配置，不改变常规追价使用的边际利润率底线。边界相等时视为满足，例如试算结果恰好为 `-2.00%` 时可以容忍。

## UI 与交互

### AZ提醒列头

`AZ提醒` 的第二行列头替换为紧凑的批量操作区：

- 保留“小差额提醒”列名。
- 显示百分比输入框，默认 `-2.00%`。
- 显示“一键容忍（N）”按钮，`N` 为当前页面全部产品中满足容忍资格的 PPV 数量，不受表格搜索和筛选影响。
- 当 `N = 0` 时按钮禁用。
- 自营渠道继续隐藏该列及其批量容忍功能。

输入框编辑后立即更新每行试算结果和按钮数量。配置值按京东换新渠道持久化，重新打开页面时继续使用；首次使用或旧数据没有该字段时回退为 `-2.00%`。

### AZ提醒行内容

有小差额提醒的行显示：

- 原有小差额或高价值小差额说明。
- 取整后的容忍试算价。
- 试算追后边际利润率。
- “可容忍”或“低于容忍底线”状态。

没有小差额提醒的行继续显示 `-`。不提供逐行容忍按钮。

### 二次确认与批量应用

点击“一键容忍（N）”后使用二次确认，至少展示：

- 将调整的 PPV 数量。
- 当前容忍边际底线。
- 说明目标价已经按现有价格规则向上取整至不低于 `tm裸机价`。

取消确认时不修改任何数据。确认后，在一次状态更新中将全部可容忍 PPV 的手动推荐追后价写为各自的容忍试算价。随后复用现有手动改价链路，自动重新匹配补贴并刷新追后利润率、竞争力、预计投入费用和保存快照内容。

批量应用后，目标 PPV 已经满足 `recommendJdPrice >= tm裸机价`，因此自动退出小差额提醒和可容忍名单，按钮数量同步下降。

## 数据结构与计算边界

### 渠道状态

京东换新渠道状态增加 `smallGapToleranceMargin`，默认 `-0.02`。沿用当前渠道状态的本地持久化与归一化流程，不新增独立存储系统。

### 行级试算结果

`CalculatedProduct` 增加可选的小差额容忍元数据：

- `smallGapTolerancePrice`
- `smallGapToleranceMargin`
- `smallGapToleranceEligible`

小差额评估逻辑负责产生这些字段；表格只展示结果和汇总可容忍名单，不自行复制补贴或利润公式。

### 批量写入

`MainTable` 将可容忍的 `ppv -> 容忍试算价` 映射一次性传给 `App`。`App` 合并写入现有 `manualRecommendPrices`，不新增第二套价格覆盖状态。

## 竞争力口径统一

以下新计算统一使用 `>=`：

- 追前 JD 物品价 vs TM 物品价。
- 追前 JD 到手价 vs TM 到手价。
- 追前 JD 物品价 vs ZZ 物品价。
- 追前 AHS 补贴后报价 vs ZZ 到手价。
- 追后对应的四项正式竞争力指标。
- 手动改价后的四项竞争判断。
- 小差额提醒的“已经具备竞争力”判断。
- 导出 Excel 中的四项追后竞争公式。

竞品价格仍需大于 0；缺失或为 0 时不判定为有竞争力。

竞争力汇总继续读取产品行上的布尔竞争结果，因此新测算、新保存快照和新正式落数自然采用 `>=`。历史批次已经保存的布尔结果和竞争力指标不重新计算、不迁移、不覆盖。

## 文档更新

项目业务说明中原有“比较符必须使用严格 `>`”改为“有效竞品价格存在时使用 `>=`”，并明确历史快照不回溯。

## 异常与边界

- `tm裸机价 <= 0`：不产生提醒或容忍资格。
- 基准价 `<= 0`：试算边际利润率按 0 处理，仍按配置底线比较。
- 没有补贴规则：沿用现有手动改价的补贴回退口径。
- 取整目标无法在现有搜索范围内找到：不进入可容忍名单，并保留提醒说明。
- 容忍底线输入限制沿用现有利润率输入规则，按百分数输入并约束在 `-50%` 至 `50%`。
- 二次确认打开后若数据发生变化，以点击时最新的可容忍名单生成确认内容并应用。

## 验证标准

1. 首次打开时容忍底线为 `-2.00%`，修改后刷新页面仍保留。
2. `AZ提醒` 列头显示输入框和“一键容忍（N）”，自营渠道不显示。
3. `tm裸机价 = 1068` 时容忍试算价为合法价格 `1100`，不会采用低于目标的 `1060`。
4. 试算价格跨越补贴门槛时，使用新档位补贴重算边际利润率。
5. 试算边际利润率等于容忍底线时进入名单；低于底线时不进入。
6. 取消二次确认不改变任何手动价格；确认后所有符合条件的 PPV 一次性应用。
7. 批量应用后，相关行退出小差额提醒，并刷新利润率、竞争力和投入费用。
8. JD 与竞品价格相等且竞品价格有效时，页面、汇总、新快照和 Excel 公式均判定为有竞争力。
9. 已保存的历史正式落数保持原有值。
10. 类型检查、针对性计算测试和生产构建通过。

## 测试策略

- 为向上取整到 `>= tm裸机价` 增加边界测试，包括刚好合法档位和必须跨到下一百位的价格。
- 为竞争力相等边界增加追前、追后、手动改价和 Excel 公式测试。
- 为小差额评估增加补贴跨档、恰好达到容忍底线、低于底线和无有效 TM 价格测试。
- 为批量应用增加确认取消与一次性合并手动价格测试。
- 最终运行 `npm run test:pricing-export`、新增的针对性测试、`npm run lint` 和 `npm run build`。
