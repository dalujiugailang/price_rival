# 品牌字段与品牌竞争力趋势设计

## 目标

daily price API 按 PPV 返回并匹配【品牌名称】，工作台与 Excel 在 BJ 后增加 BK【品牌名称】；品牌竞争力面板按所选品牌展示正式历史落数与今日草稿的四项竞争力趋势。

## 品牌来源与回填

- 历史品牌已完成一次性回填；后续 daily price 查询范围只取本次上传工作台的 PPV，去重后一次查询，不再重复查询或回填历史。
- 本项目读取上游字段别名【品牌名称】、【品牌】、`brandName`、`brand`。
- 上游当前响应尚未提供品牌字段。代理接口在字段缺失时根据 API 返回的 `sku名称` 或 PPV 中明确出现的品牌标识补充【品牌名称】。
- 补充规则只覆盖已核验的品牌标识：OPPO、REDMI、iQOO、vivo、一加、努比亚、华为、小米、真我、荣耀。
- 现有 API 未匹配的 34 个 PPV 均包含明确机型品牌；已通过各品牌官网核对对应品牌后使用同一规则补齐。
- 当前工作台由 API 品牌覆盖旧的系列/型号推测品牌。
- 已匹配品牌写回共享历史所有含 PPV 明细的快照，只修改 `product.brand`，不修改价格、补贴、利润、正式标记或已保存竞争力总分，并记录审计日志。
- API 同步状态显示品牌匹配数量、历史更新批次数与明细数；仍不能确认的 PPV 显示完整清单。

## 工作台与导出

- `DailyPriceRow` 新增 `brandName` 与 `matched`。
- 工作台固定列在 BJ 后追加 BK，列名保持【品牌名称】，显示 `product.brand`。
- Excel 固定列同样在 BJ 后追加 BK【品牌名称】；原始字段仍完整保留在后方。
- 历史快照导出的线上测算和全字段快照补充品牌名称，便于追溯。

## 品牌竞争力趋势

- 品牌趋势复用“历史追平周期竞争力波动走势”主图，不再新增第二个图表。
- 主图右上角原“走势分析”提示框替换为品牌下拉框，品牌集合来自历史明细和今日工作台；默认选择【全部品牌】。
- 选择【全部品牌】时保持原有总趋势；选择具体品牌时，同一张图切换为该品牌趋势。
- 上方四项竞争力卡片与品牌筛选联动，按当前所选数据源内该品牌的 PPV 明细重新加权；切回【全部品牌】恢复整体指标。
- 每个时间节点先按 `product.brand` 过滤，再复用现有 `calculateCompetitivenessMetrics`，继续按 PPV 近 30 天报价量/访客数加权。
- 四条折线与总趋势保持同一口径、颜色、Tooltip 和图例：天猫到手价、天猫物品价、AHS 补贴后对转转到手价、转转物品价。
- 品牌趋势继续使用主图左下角“近15次追价 / 全部”范围。
- 某期没有所选品牌明细时不生成该品牌节点，避免把“无样本”误画为 0%。
- 现有 7 期正式记录为纯汇总数据，`products` 为空，无法拆分品牌，品牌趋势不展示这些节点；今日工作台与今后含明细的正式落数正常展示。

## 服务端变更

- 新增批量品牌回填接口，接收 `channelId` 与 `brandsByPpv`。
- 数据库事务逐批更新 `payload_json` 中产品的 `brand`，返回更新批次、明细数量，并写入 `BATCH_BRAND_BACKFILL` 审计。
- 回填为幂等操作；品牌未变化时不写数据库。

## 验证

- 品牌识别测试覆盖 API 原字段优先、10 个核验品牌、未知文本留空。
- 品牌趋势测试覆盖按品牌过滤、四项加权、正式历史排序、今日草稿、无品牌样本跳过。
- 数据库回填测试覆盖只改品牌、保留历史竞争力与其他字段、重复回填不更新。
- 工作簿/列测试确认 BK 位于 BJ 后且值为品牌名称。
- 运行全部专项测试、TypeScript 检查、生产构建和 5001 页面交互验收。
