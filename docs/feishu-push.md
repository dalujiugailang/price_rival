# 竞争力简报推送

控制台右上角「推送飞书」→重新读取服务器历史，并按历史页相同的保存时间排序默认选中最新批次；若尚未确认或仅汇总，提示处理并禁止预览，不自动回退旧批次→选择已保存且已确认竞争力的明细批次→选择品牌/新机系列→搜索并选择人员或获取机器人所在群→生成预览→确认发送。默认接收人为陈誉钧：仅在服务端成员目录中姓名唯一匹配且已启用时自动选中对应账号，未匹配或重名时需手动搜索选择。每次最多20个对象。

## 飞书应用配置

复用现有 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`；使用应用机器人身份，不使用群自定义机器人 Webhook。`APP_URL` 必须配置为接收者可访问的生产 HTTPS 域名。

应用后台需启用机器人能力，并按实际使用开通、发布相应权限：

- 以应用身份发送消息：`im:message:send_as_bot`（或官方允许的同等消息权限）。
- 上传图片：`im:resource`（以后台当前权限名称为准）。
- 获取机器人所在群列表：相应群信息读取权限，如 `im:chat:readonly`。
- 搜索/核验联系人：沿用现有成员目录接口所需权限和通讯录范围。搜索授权过期时重新登录。

单聊接收人须在应用可用范围内；群聊须先添加该应用机器人。登录成功本身不能证明机器人或消息权限已开通。配置检测只判断应用凭据是否存在，权限可用性以接口实际响应为准。

## 数据和权限

推送要求同一渠道的工作台编辑权限及竞争力查看权限，后端独立检查。服务端从 SQLite 正式批次返回追踪器渲染所需数据及摘要，前端直接复用 CompetitivenessSummary 原组件，截图包含 Benchmark 指标和历史趋势折线图，省略底部明细审计表。截图以 PNG 回传，服务端核对批次与历史摘要、格式及尺寸后保存。图片来自前端渲染，不提供服务端视觉内容认证。指标计算及品牌归一规则与页面共用；有效权重不足时显示暂无有效数据。全范围沿用批次已保存指标，筛选范围按明细重新计算。

简报与 PNG 保存在现有业务 SQLite 的 `feishu_push_previews` 表。卡片详情链接带 `reportId`，打开推送时的简报，并提供原批次走势/明细入口；后续数据变化不改写已发简报。访问要求该渠道竞争力页面权限，无权限不自动授予。未登录走原飞书登录，OAuth 回调安全返回原链接。

发送前预览有效期20分钟，并重新核验批次摘要及接收对象。成员接口必须成功返回相同 open_id；若姓名字段未返回，仅允许用系统内同一 open_id 的已启用成员记录补充显示姓名，并在结果及审计中标记姓名来源。账号不匹配、接口失败、已离职或系统停用时仍拒绝发送。权限管理的成员新增校验仍要求飞书实时返回姓名。新生成的预览不能绕过“相同内容+接收对象”去重。发送记录存于 `feishu_push_deliveries`，并写入操作日志。结果含每个对象的消息ID和状态。网络超时/崩溃留下的状态需核查，不自动重新发送；确定失败也保留记录，不提供盲目重试。API成功表示飞书接受消息，不表示已读。

备份既有 SQLite 时一并备份这两个表。部署需重新构建镜像（新增 sharp 和 html-to-image），不能只复制 dist。图片中的字体由浏览器实际渲染。不要记录或将 App Secret、租户 token 传给前端。

## 验收

`npm run lint`、`npm run build`、`npm run test:feishu-push`。新测试使用模拟飞书客户端，覆盖权重、筛选、缺失分母、PNG校验、权限、并发去重、状态未知、持久化、简报不变及安全返回路径，不发送真实飞书消息。测试数据留在系统临时目录。

正式验收先给核验后的陈誉钧发送一个批次，核对机器人身份、手机显示、指标、链接、登录返回及重复点击行为，再开放群推送。
