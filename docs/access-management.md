# 人员权限管理

京东换新导航底部新增「权限管理」，仅管理员可见。按人员配置「只读 / 可编辑」「启用 / 停用」和渠道下的具体页面。修改操作权限不会自动改变查看范围；新增默认只读，默认查看京东换新工作台、竞争力走势和高出清单。只读成员可在授权页面筛选及导出，不能上传、改价、保存或删除。

## 首次迁移与持久化

权限保存在现有 SQLite 数据卷的 `access_members`，目录缓存为 `access_directory`，迁移标记为 `access_migrations`。首次从 `FEISHU_ALLOWED_OPEN_IDS` 和 `FEISHU_READ_ONLY_OPEN_IDS` 原样迁移现有成员；已有编辑和只读范围保留。`FEISHU_ADMIN_OPEN_IDS` 指定已有成员中的管理员。可选的 `data/access-bootstrap.json` 保存本部署的默认管理员 ID 及姓名、部门显示信息；文件位于 Git 忽略的数据目录，不随源码发布。姓名、部门仅供显示，不会凭此增加授权。

新部署应先在环境文件中填写 `FEISHU_ADMIN_OPEN_IDS`；如需保留旧部署的显示信息，可在持久化数据目录创建 `access-bootstrap.json`，格式为 `{"admins":["ou_example"],"profiles":{"ou_example":{"name":"示例管理员","department":"示例部门"}}}`。环境变量中的管理员配置优先于此文件，`admins` 也必须属于已有个人白名单。文件缺失时不内置任何人员信息；已完成迁移的权限继续从数据库读取。

迁移完成后，以数据库为准，重启和旧环境变量不能恢复已停用账号。部门白名单不再自动授权。普通界面不能授予管理员权限，管理员本人的权限受保护。多人同时修改会检查版本，过期修改返回 409 并要求刷新。

## 查看范围与接口

范围格式为 `tradeIn.workspace` 等，含京东换新、京东自营各六个业务页面：工作台、数据源、历史、竞争力走势、高出清单和操作日志。权限管理为管理员专有入口。

服务端每次请求重新读取当前成员角色、范围和状态。前端每 15 秒、重新聚焦或收到权限拒绝时刷新，权限版本变化后重建页面以清除旧状态。读写、批次详情、日志和导出接口分别验证范围。仅走势或高出清单授权不会返回完整底表、基准价、利润或投入费率输入；工作台只返回最新完整明细，历史授权可读完整历史。无权限页面不加载原有本地工作区缓存。前端不再内置业务底表或发布 public 下的业务 Excel 文件。

只读数据源页面展示最新共享快照的来源统计；旧快照未保存文件记录时显示来源表与行数，新保存快照附带上传记录。编辑工作区继续使用浏览器中的本地数据，新浏览器从上传开始。

## 新增成员

可按姓名搜索，或输入飞书 open_id。通讯录姓名搜索使用管理员本次飞书登录获得的 user access token，仅存于服务器内存，最多两小时；重启或到期后需重新登录。飞书应用仍需具备姓名搜索权限。没有搜索授权时，可让同事先登录一次，再从已识别成员中按姓名找到；账号未开通时仍被拒绝访问。新增时服务端会再次通过应用所属租户的通讯录核对账号身份及离职状态，不接受客户端填写的姓名作为身份依据。

## 验收与发布

运行 `npm run test:access`、`npm run test:auth`、`npm run lint`、`npm run build`。权限测试使用独立临时数据库，覆盖迁移幂等、管理员保护、版本冲突、旧会话停用、跨渠道读取、只读写入拒绝和字段裁剪。页面验收仅使用隔离测试库，不在生产创建测试人员。

权限管理与历史快照页面兼容。发布前备份源码、镜像和 SQLite，再同步代码并重建容器；不覆盖 `.env` 和持久化数据卷。发布后按发布前基线核对成员、角色分布、业务快照数量和真实登录。回退旧鉴权代码会重新使用环境白名单，如已经调整过权限，应同时核对旧名单避免恢复已撤销的授权。
